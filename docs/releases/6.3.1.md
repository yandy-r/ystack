# Release 6.3.1 — 2026-11-05

## Summary

ycc 6.3.1 fixes duplicate ycc skills, agents, commands and MCP servers in opencode. `install` and `sync --target opencode` now add the `@yandy-r/ycc-opencode` npm plugin to `opencode.json` instead of copying the bundle into `~/.config/opencode`, and retire the old copies that ycc can prove it wrote.

## Added

- `install --target opencode` writes one `plugins` entry. `--mode local` (default) points it at this checkout's `packages/opencode/ycc-opencode`; `--mode repo` pins `@yandy-r/ycc-opencode@<version>` from npm. `--package @yandy-r/ycc-opencode` does the same.

## Changed

- `@yandy-r/ycc-opencode` is now the primary opencode package (no longer experimental or opt-in). Settings, rules (`AGENTS.md`) and the opt-in plugin catalog stay on the installer.
- The generated `.opencode-plugin/opencode.json` no longer lists the `./ycc-sensitive-guard` plugin or an `mcp` block; the package ships both.
- Release notes no longer mark the npm package "not yet published".

## Removed

- opencode file copies (skills, agents, commands, shared helpers, the guard directory) and the opencode MCP merge.
- `--mcps`, `--agents`, `--commands`, `list-mcps`, `--skills-home` and its duplicate-skills prompt. `--skills` and `--with-deps` now apply to the agents target only.

## Fixed

da778507 fix(opencode)!: install the @yandy-r/ycc-opencode npm plugin instead of copying the bundle (YAN-1973) (#536)

- A ycc-written, bare or `@latest` `@yandy-r/ycc-opencode` entry is replaced in place, keeping its `options`. A pinned version you set yourself, or another checkout's directory, is kept unless you pass `--force`.
- The legacy cleanup runs only after the package is confirmed loadable: `package.json` in local mode, the npm release in repo mode, and opencode 2.0.30 or later when `opencode` is on PATH. It removes only byte-identical copies, owned `mcp.servers` entries and the owned guard item. Edited and foreign entries are kept, and a symlinked `opencode.json` is refused.

## Upgrade Notes

**Breaking for scripts that pass removed flags.** Run `ycc install --target opencode` (or `sync --target opencode --intent base`) once. It replaces your plugins entry and removes the old copies under `~/.config/opencode` that ycc can prove it wrote, then restart opencode.

- Drop `--mcps`, `--agents`, `--commands`, `--skills-home` and `list-mcps` from scripts. `--skills` and `--with-deps` still work for `--target agents`.
- To keep a specific pinned `@yandy-r/ycc-opencode@<version>` entry, leave it; the installer reports and keeps it. Pass `--force` to replace it.
- Use `--mode repo` for the published npm package, or the default local mode to load this checkout.
